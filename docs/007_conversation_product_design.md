# 007 · 对话消息与输入区产品设计

## 范围与文档职责

本篇定义工作台第三栏的消息阅读、输入与会话配置交互。[003](003_web_app_design.md) 负责整体三栏布局，[006](006_settings_page_design.md) 负责全局设置，[001](001_codex_acp.md) 与 [002](002_dsh_acp.md) 负责 Agent 协议，[005](005_sqlite_storage_design.md) 负责持久化。对话输入区的控件位置与操作以本篇为准。

**模型选择、Effort、Fast mode 必须直接位于消息输入框下方，用户无需先点击右上角会话配置按钮。输入区不显示“Codex · 本地工作区”“DSH · 本地工作区”等固定文案。** Agent 身份由左侧选中图标、会话标题和消息作者表达。

## 第三栏结构

从上到下划分为会话标题区、消息阅读区、输入区。标题区保留项目/会话名称、连接状态、连接或继续会话、断开等操作，不提供重复的模型、Effort、Fast mode 配置入口。

```text
┌──────────────────────────────────────────────────────────────┐
│ 项目 / Agent      会话标题                    连接状态 / 操作 │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│                    消息与 ACP 输出                            │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ 待审批操作 / 连接提示 / 保存失败（有对应状态时显示）             │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ 输入消息，多行编辑…                                       │ │
│ │                                                          │ │
│ ├──────────────────────────────────────────────────────────┤ │
│ │ 模型 [当前模型 ▾]  Effort [当前级别 ▾]  Fast mode [开关]    │ │
│ │ 操作模式 [当前模式 ▾]（Agent 提供时）       [停止] [发送]   │ │
│ └──────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

示意中的“当前模型”“当前级别”均来自 Agent，不是默认配置。桌面宽度充足时，控件与发送操作可合并为一行；模型、Effort、Fast mode 始终位于文本编辑区下面、同一个输入容器内。它们不放在输入框上方、消息列表底部的浮层或全局设置页。

输入区在第三栏底部保持可见。文本框高度随内容增长至上限后内部滚动，消息区使用剩余空间独立滚动；输入框增长不把控件行或发送按钮挤出视口。

## 会话配置控件

| 控件 | 展示与操作 | 值的来源 |
| --- | --- | --- |
| 模型 | 直接展示当前模型；点击打开锚定该控件的选择菜单，选中项有明确标记 | 当前会话公布的模型选项与确认值，保留分组与可读名称 |
| Effort | 直接展示当前推理强度；点击选择 Agent 提供的级别 | 当前会话实际提供的推理强度选项，不硬编码 Low/Medium/High 等集合 |
| Fast mode | 独立的有文字标签的开关，明确显示开启/关闭 | Agent 实际提供的快速模式配置及确认值 |
| 操作模式 | Agent 提供模式时，显示当前模式及可选项 | `availableModes`、`currentModeId`，通过模式协议提交 |
| 其他会话选项 | 输入框下方的“更多选项”入口，使用就近菜单或面板 | 尚未放入上述常用控件的真实配置项 |

模型、Effort、Fast mode 不收进“更多选项”。选项较多时选择菜单内部滚动，菜单不得遮住整个工作台。仅有一个可选值时展示只读值，不伪装为可切换。

Fast mode 与 Effort 是独立设置：开启快速模式不代表降低推理强度；切换 Effort 不自动关闭或开启快速模式。快速模式不改变审批、安全权限或自动批准行为。不展示未经 Agent 提供的速度、费用或用量承诺。

### 能力识别与不可用状态

- 配置的 ID 和 value 是不透明协议值，界面使用 Agent 提供的可读名称，提交原始 ID/value。
- 控件识别优先使用协议中的语义分类；协议没有足够分类时，由对应 Agent 的明确映射识别。不能凭任意名称包含“fast”就把未知选项当作快速模式，也不能将 Codex 的配置 ID 或值套给 DSH。
- Fast mode 只有在对应 Agent 明确支持布尔开关，或提供可明确映射为开/关的选项时才能操作。无法确认语义时保留为其他真实配置项，不制造开关。
- 尚未连接或建立会话时，三个常用位置显示不可操作的“连接后可用”；加载期间显示“读取中”。保留布局，避免按钮反复跳动。
- 会话已就绪但未提供模型选择、Effort 或 Fast mode 时，对应位置显示只读/禁用的“Agent 未提供”，并有可访问说明。缺少快速模式能力不等于快速模式已关闭；未知当前模型不能显示为某个猜测值。
- 切换模型后使用 Agent 返回的完整配置集合刷新控件。若新模型不支持原 Effort 或 Fast mode，则显示 Agent 返回的新状态，不保留失效的可选值。

## 配置修改的状态与反馈

会话配置只作用于所属会话，不是 Agent 全局偏好，也不影响其他项目中的对话。

| 会话状态 | 控件与输入行为 |
| --- | --- |
| 未选择会话 | 输入不可发送，配置不可操作；提供选择或创建会话的提示 |
| 连接、认证、建会话或恢复中 | 配置不可操作，保留已有草稿；显示对应进行状态 |
| 空闲且已连接 | 支持的配置可修改；有有效文本时可发送 |
| 正在提交配置 | 展示“正在应用”，禁用配置控件和发送，防止与 prompt 并发；保留文本编辑和草稿 |
| 正在回复或等待审批 | 配置不可修改，显示本轮使用的已确认值；保留停止入口，不排队偷偷应用配置 |
| 正在取消 | 显示“正在停止”，不允许发送或修改配置，直到收到最终响应或连接关闭 |
| 断线 | 展示断线状态，配置不可操作；已有草稿和消息保留，允许按实际能力恢复 |

修改使用以下顺序：

1. 从当前会话捕获连接、会话 ID 和选项 ID，验证目标值属于当前公布的可选集合。
2. 提交配置请求，将状态标为“正在应用”；旧值仍是已确认值，不提前显示为成功。
3. 成功后以完整响应或配置更新通知刷新实际值；不只替换某个本地标签。
4. 失败时恢复最后确认的配置，并在控件行附近显示原因和可重试操作；草稿不丢失、不自动发送消息。
5. 等待期间用户切换会话或进入设置，结果仍更新原会话，不覆盖后来显示的会话，也不强行把用户拉回。

配置更新通知按所属连接和 sessionId 路由。断线后迟到的响应不得让新连接显示为“应用成功”。界面展示的是最新确认状态，不推断未发送的后续变更。

重新进入历史会话时，从 Agent 的恢复结果读取配置；不把浏览器缓存当作已生效配置。刷新后不自动重放配置写入。改变配置不修改历史消息内容；已有消息没有记录使用的模型或 Effort 时，不补造历史标签。

## 输入、发送与认证提示

- Enter 发送，Shift + Enter 换行；输入法组合期间 Enter 不提交。
- 只有会话就绪、没有配置请求或进行中的轮次、文本非空时才能发送。发送和停止位于输入框下方操作区，不能与 Fast mode 混为一个开关。
- 用户提交时捕获所属会话和草稿；发送中的会话切换不改变消息归属，也不把内容投递到新选中的 Agent。
- 输入框保留各会话独立草稿。连接、配置或保存失败通过具体提示表达，不用清空输入框表示失败；不自动重发 prompt。
- “Codex · 本地工作区”及同类固定副标题不占用控件行，也不换成另一条重复的 Agent 身份文案。
- 需要 Agent 认证时，在输入区附近的连接提示中显示明确认证操作，使用 Agent 实际公布的方法。用户不需要猜测“去右上角配置”才能认证；不增加 API Key 输入或密钥回显。
- 配置成功不插入伪造的 Agent 回复。非必要提示不持续占用输入空间；错误与未保存状态必须持续可见，直到解除或由用户明确处理。

## 消息内容与阅读体验

| 内容 | 产品定义 |
| --- | --- |
| 用户消息 | 清楚区分作者和正文；保留换行，避免用原始协议 JSON 表示普通消息 |
| Agent 回复 | 同轮连续文本片段合并为连续内容，支持安全 Markdown、列表和代码块，不为每个片段创建消息卡 |
| 思考内容 | 与正式回复区分，可折叠；仅展示 Agent 实际提供的内容，不生成虚假的思考状态或文本 |
| 工具调用 | 同一会话内按 toolCallId 更新一张卡片，概览显示名称与状态，参数和结果在详情展开 |
| 计划 | 展示代理提供的步骤和完成状态；更新原计划，不把每次状态变化追加成另一份计划 |
| 待审批 | 显示明确的操作对象、详情和原始选项；只能回答所属连接的未决请求，离开页面不自动批准 |
| 结束或取消 | 以最终响应判断结束；发送 cancel 通知后仍显示正在停止，不提前标记成功或完成 |
| 错误与通知 | 区分模型/连接错误和本地保存错误；提供简短说明及必要详情，不把系统错误伪装成 Agent 回答 |
| 其他 ACP 事件 | 使用可折叠详情，不默认把原始 JSON 铺满消息区 |

消息正文以稳定阅读底色为主，玻璃效果用于导航和输入控件；不为每条回复叠加模糊背景。代码块可复制，过长代码在自身容器内横向滚动。禁用消息中的原始 HTML 执行和不安全链接。

用户在底部时跟随新内容；向上阅读时保持位置，只提示有新内容，点击“回到底部”后恢复跟随。工具状态、审批卡、配置反馈或输入框高度变化都不能抢走历史阅读位置。切换会话或进入全局设置后返回，保留该会话的滚动位置和展开状态。

后台会话仍接收输出、保存和审批通知。运行/待审批提示出现在所属会话与 Agent 图标上；只有选择该会话后才在第三栏显示其内容。

## 响应式与可访问性

- 桌面控件使用紧凑的标签、当前值和清晰点击区域，选择项不得依靠颜色表达选中状态。
- 输入区变窄时控件自动换行，发送/停止保持可见；模型、Effort、Fast mode 不因窄屏被移动到右上角或藏进“更多选项”。
- 长模型名称允许截断，但聚焦、悬停或展开选择菜单时可以读取完整名称；页面不能因此出现整体横向滚动。
- 使用键盘可依次到达文本框、模型、Effort、Fast mode、其他模式和发送；菜单支持选择、取消并把焦点返回触发控件。
- Fast mode 有文字标签与开关状态；禁用说明可被辅助技术读取，不能仅依赖 hover tooltip。
- 遵循全局深浅主题、减少透明和减少动态效果设置；流式输出不叠加逐字装饰动画。

## 模块边界与验收标准

| 模块 | 职责 |
| --- | --- |
| `web/ui/pages/workspace-shell.ts` | 输入框、下方配置行和发送操作的稳定布局，标题区只保留会话/连接操作 |
| `web/ui/components/composer.ts` | 根据会话状态协调输入、发送、停止和下方配置控件 |
| `web/ui/components/session-options.ts` | 模型、Effort、Fast mode、操作模式和其他配置的控件渲染、交互与局部反馈 |
| `web/acp/agents.ts` | 各 Agent 配置项的明确语义映射，不提供未经协商的可选值 |
| `web/acp/client.ts` | 配置验证、协议调用、状态互斥和确认结果，不依赖 DOM |
| `web/domain/workspace.ts` | 会话归属、草稿、消息、独立连接与保存，不根据当前可见页面路由回复 |
| `web/ui/components/messages.ts`、`permissions.ts` | 消息阅读、工具详情与所属请求审批 |
| `web/ui/styles/composer.css` | 输入区及配置行的间距、换行和状态样式，复用全局主题 |

验收要求：

1. 进入已连接对话后，输入框下方直接出现模型、Effort、Fast mode 的实际状态，无须点击右上角配置。
2. 第三栏右上角不再提供上述配置入口；输入区不出现任何“Agent · 本地工作区”固定文案。
3. 菜单只含 Agent 实际公布的可选项；缺少能力、未知值和加载中状态有明确区分，不能伪造 Fast mode 关闭或默认模型。
4. 配置请求期间不能发送；成功以确认响应更新，失败恢复旧值并保留草稿。
5. 切换模型后相关选项随完整配置刷新；Fast mode 与 Effort 不互相替代，不改变工具审批权限。
6. 运行、审批或取消期间不能偷偷修改配置；其他空闲会话的配置不受该会话影响。
7. 配置等待中切换 Agent、会话或全局设置，迟到结果不会覆盖当前会话或改变导航位置。
8. 长模型名、窄屏和深浅主题下，常用三个配置控件及发送/停止仍可发现、可操作；键盘和辅助技术可读取标签与状态。
9. 流式消息、工具更新、计划、审批、错误和历史回放不串会话、不重复追加；阅读位置和展开状态保持。
10. 认证失败、配置失败、模型错误和保存失败分别反馈，不通过清空草稿、伪造回复或自动重发掩盖问题。

操作变更与验收执行结果统一记录在 [CHANGELOG.md](../CHANGELOG.md)。
