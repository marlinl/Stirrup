# 003 · Web 启动与页面设计

## 目标与范围

Stirrup 的 Web 界面分为**登录页**与**登录后的工作台**两个层级。工作台包含对话和设置视图，共用三栏布局，整体采用 Apple Liquid Glass 风格。对话视图依次为 Agent 图标栏、按项目分组的 Session 栏、对话与 ACP 输出区；设置视图依次为同一图标栏、设置分类、设置内容。

设置布局与操作由 [006 · 设置页面](006_settings_page_design.md) 定义，数据持久化由 [005 · SQLite 存储](005_sqlite_storage_design.md) 定义，模块边界见 [004 · 代码分层](004_code_structure.md)，消息与输入区的详细产品定义见 [007 · 对话消息与输入区](007_conversation_product_design.md)。

[001 · Codex ACP 对接](001_codex_acp.md) 与 [002 · DSH ACP 对接](002_dsh_acp.md) 分别负责协议与能力边界。本篇负责页面、启动和交互关系；新页面不得绕过已有协议能力检查。范围覆盖 Web 产品所需的启动与交互，不扩展到多用户平台或整体服务架构。

## 页面层级、路由与启动流程

| 页面 | 路径 | 职责 |
| --- | --- | --- |
| 登录页 | `/login` | 登录 Stirrup，显示认证状态与错误 |
| 工作台：对话 | `/chat` | 切换 Agent、选择项目与会话、发送消息、呈现 ACP 输出 |
| 工作台：设置 | `/settings/:section` | 同一三栏内选择设置分类并操作，具体路由见 006 |

根路径 `/` 在检查登录状态后进入对应页面。设置是工作台内有独立路由的三栏视图，不使用弹窗；添加项目等短操作可使用弹层；会话配置在输入框下方操作，选择菜单就近展开，详见 007。主对话页可通过查询参数记录当前 Agent、项目及会话的应用内标识，地址中不放凭据或本地绝对路径。

### 本地启动

保留 npm / TypeScript / Vite 的现有项目入口，Node.js 要求为 24.9.0+：

```sh
npm install
npm run dev
```

`npm run build` 构建前端，`npm run preview` 用于带本地 ACP 转接的构建预览。单独托管 `dist/` 无法操作本地代理。以上命令均使用本篇的新页面与本地登录入口。同一数据目录只运行一个 Web 实例。

### App 环境参数与启动约束

`local/config/startup.ts` 与 `local/config/site.ts` 分别读取项目根目录 `.env` 的监听配置和站点配置；`vite.config.ts` 将其应用到 `npm run dev` 和 `npm run preview`。首次配置可参考 `.env.example`，已有 `.env` 只追加或修改所需启动参数，不覆盖无关配置。

| `.env` 参数 | 默认值 / 来源 | 约束与生效时机 |
| --- | --- | --- |
| `STIRRUP_HOST` | `127.0.0.1` | Web 监听地址，支持 IP 地址或主机名，包括 `0.0.0.0` / `::` 通配监听；启动时读取，修改后重启 |
| `STIRRUP_PORT` | `5173` | Web 监听端口，1–65535 的十进制整数；dev 与 preview 使用同一值，启动时读取，修改后重启 |
| `STIRRUP_SITE_URL` | 缺省为 `http://localhost:<实际监听端口>` | 浏览器访问的完整站点来源；HTTPS 域名，可含非默认外部端口；仅开发环境允许 `http://localhost`。不含路径、查询、fragment 或用户信息，不接受 IP 作为 RP ID。启动时读取，修改后重启 |

Passkey 用户、公钥凭证、个人偏好和登录有效期由 SQLite `personal_settings` 保存，见 005。旧 `.env` 账号、公钥和有效期项不读取、不导入；没有个人记录时进入首次初始化。

典型监听配置：

```dotenv
STIRRUP_HOST=127.0.0.1
STIRRUP_PORT=5173
STIRRUP_SITE_URL=https://chat.example.com
```

启动行为必须满足：

1. 监听参数采用「显式 `--host` / `--port` > 根目录 `.env` > 内置默认值」的优先级。根目录 `.env` 本身必须有效；命令行覆盖值经过同样校验。Shell 中同名 `STIRRUP_*`、`.env.local`、`.env.development`、`.env.production` 不覆盖本表配置。缺少 `.env` 可用默认监听配置启动并进入首次绑定流程；显式空地址/空端口、非法值或文件不可读取时直接退出，不静默回退。
2. dev 与 preview 均强制 `strictPort`：端口被占用立即失败，不自动递增、不选择随机端口。绑定失败必须释放已打开的数据库连接。权限不足或系统不支持所选地址时使用实际监听错误，不伪装为启动成功。
3. 显式 `STIRRUP_SITE_URL` 不随内部监听地址、端口或 CLI 覆盖而改变；缺省开发地址随实际监听端口计算。
4. `STIRRUP_HOST` 控制绑定地址。HTTP 与 ACP 保留登录鉴权与严格同源校验。
5. 不限制监听地址为回环地址。允许 `0.0.0.0`、`::`、网卡 IP 或主机名，以及 Vite 的无值 `--host` 通配监听；地址不包含协议、端口、路径或空白，主机解析和能否绑定由操作系统决定。
6. App 配置仅在服务端读取，不设置 `VITE_` 前缀、不注入前端 bundle、不通过设置接口回显原始 `.env`。未配置 Passkey 不阻止 HTTP 启动，但受保护的工作台接口仍不可访问。监听地址、端口与站点地址不热更新；个人设置在数据库中保存，按登录章节的读取时机生效。

Agent 运行环境另行区分：`CODEX_API_KEY` / `OPENAI_API_KEY`、`DEEPSEEK_API_KEY`、`DSH_HOME`、`AGY_PATH` 由启动进程的环境继承给对应 Agent，或由 Agent 自己读取其本地配置；Stirrup 不自动把根目录 `.env` 的任意变量写入进程环境。它们不属于上述 App 监听/登录参数，也不应使用 `VITE_*` 暴露到浏览器。固定 Agent 命令与环境策略见 001、002、008。

启动验收应覆盖：缺省参数、dev/preview 同端口、合法自定义地址和端口、非法值快速失败、端口占用不递增且释放数据库连接、命令行覆盖与通配监听、外部站点地址独立于内部端口，以及 HTTP/ACP 的 Host 和 Origin 校验。

### 启动流程

启动顺序：

1. 启动本地 Web 入口，先读取并校验项目根目录 `.env` 的监听配置，再创建本地运行时并绑定指定地址和端口。
2. 浏览器检查 Stirrup 登录状态；检查期间显示轻量加载状态，不闪现历史对话。
3. 未登录进入 `/login`；已登录默认进入 `/chat`，加载项目、会话索引和界面偏好。已登录直接访问设置路由时保留目标分类，未登录时由登录流程校验并恢复合法的工作台目标路由。
4. 恢复上次选中的 Agent、项目及会话；记录不存在时退回相应空状态。
5. 用户新建或继续会话时才建立需要的 ACP 连接。打开页面或浏览历史不自动提交 prompt。

Stirrup 登录与 Agent 模型认证分开：前者决定能否访问工作台，后者由 Codex / DSH / Antigravity 的实际认证能力和本地凭据决定。登录 Stirrup 不代表任意模型可用。

### 站点身份与 Nginx

`STIRRUP_SITE_URL=https://chat.example.com:8443` 对应 RP ID `chat.example.com`、预期 Origin `https://chat.example.com:8443`。RP ID 不含协议或端口，Origin 不含路径。网站身份来自服务端配置，不从客户端提交的域名或转发头推导。[WebAuthn RP 规则](https://developer.mozilla.org/en-US/docs/Web/API/PublicKeyCredentialCreationOptions#rp)

浏览器通过 HTTPS 访问 Nginx，Nginx 可通过 HTTP 转发给 Node.js。Nginx 必须保留外部 `Host`（含非默认端口，如 `proxy_set_header Host $http_host`）与浏览器 `Origin`，为 ACP 转发 WebSocket Upgrade；Node.js 仍按外部站点校验。`X-Forwarded-Host` / `X-Forwarded-Proto` 不覆盖配置，也不能用于放行其他站点。dev/preview 的允许主机包含配置域名。

HTTPS 站点的登录 Cookie 与 WebAuthn 挑战 Cookie 均带 `Secure`、`HttpOnly`、`SameSite=Strict`。缺省开发入口为 `localhost`；浏览器不会被强制导航到其他主机。局域网可通过受信任证书的 HTTPS 域名使用 Passkey；普通局域网 HTTP 不满足浏览器安全上下文要求。更换域名不会把原 RP 的凭证自动转成新站点凭证，也不能自动清空个人记录以重新开放初始化。

### 登录页与首次初始化

登录页使用居中的玻璃面板，只有 Passkey 操作，没有用户名输入或密码兜底。`GET /api/auth` 根据 `personal_settings` 是否存在记录返回 `configured`；查库失败返回错误，不将错误当作“首次使用”。

- **没有个人记录**：显示「创建 Passkey」，无需终端命令或绑定链接。服务端生成随机用户 ID、默认显示名称 `Stirrup` 及五分钟挑战，均先保留在内存。本人完成系统认证器验证后，服务端验签，在事务中再次检查表为空，然后插入唯一个人记录。公钥、凭证 ID、RP ID、签名计数器、传输方式和默认个人配置一同保存；私钥始终留在认证器中。
- **已经初始化**：只显示「使用 Passkey 登录」，拒绝再次注册。初始化成功后转为普通登录，由一次认证断言建立登录会话。注册与登录都要求 user verification；取消、过期或验证失败允许重试，不产生半初始化记录。
- 两个浏览器同时初始化时只有一个可以成功提交；失败者不能覆盖已登记的凭证。首次初始化入口面向可访问该站点的浏览器，完成后关闭注册。

认证使用 `@simplewebauthn/server` / `@simplewebauthn/browser`，校验签名、用户验证、RP ID、Origin、挑战和已登记凭证 ID。挑战绑定独立 HttpOnly Cookie，五分钟过期，验证前即消费；异步验证后再次检查有效期与持久化版本。登录更新计数器时使用乐观并发校验，禁止覆盖更新后的记录。旧 `.env` 凭证、密码账号和绑定授权文件均不参与认证，不自动导入。

登录有效期来自 `personal_settings.session_ttl_seconds`，默认 `43200` 秒（12 小时），范围 1–31536000 的整数。设置页可修改名称与有效期；有效期仅影响下次登录，不重算已有会话，不滑动续期。Cookie Max-Age、服务端绝对到期时间和 ACP 回收使用同一值；长有效期采用分段计时。修改显示名称不改变账号身份或使已登录会话失效，替换公钥或删除账号会在下次鉴权时撤销其登录与连接。

登录必须保护数据接口和 ACP WebSocket 升级入口，不能只靠前端路由。Session 与挑战保存在服务端内存，重启后重新登录；登出或到期会关闭对应 ACP 连接。协议依据见 [SimpleWebAuthn 服务端文档](https://simplewebauthn.dev/docs/packages/server)及[浏览器文档](https://simplewebauthn.dev/docs/packages/browser)。

## 主对话页：三栏布局

```text
┌──────┬──────────────────────┬─────────────────────────────────────┐
│      │ 当前 Agent           │ 项目 / 会话标题          状态 · 配置 │
│ Codex│ ＋ 添加项目          ├─────────────────────────────────────┤
│ icon │                      │                                     │
│      │ ▾ 项目 A       ＋    │                    用户消息         │
│ DSH  │   ● 会话一           │                                     │
│ icon │     会话二           │ Agent 回复                          │
│      │                      │ 工具活动 / 计划 / ACP 输出           │
│      │ ▾ 项目 B       ＋    │                                     │
│      │     会话三           │                                     │
│      │                      │ 待处理审批                          │
│      │                      ├─────────────────────────────────────┤
│  ⚙️  │                      │ 输入消息…                  停止 / ↑ │
└──────┴──────────────────────┴─────────────────────────────────────┘
 图标栏   项目 / Session 栏       主对话区
 固定窄栏 默认 20%，最多 50%       占剩余宽度
                   ↔ 拖动分隔线
```

三栏占满应用可用高度。图标栏固定；第二栏列表独立滚动；第三栏消息独立滚动，标题区与输入区保持可见。页面不依靠整体纵向滚动来寻找输入框。

### 第一栏：Agent 图标栏

- 一列图标宽度，建议轨道宽度 64px，图标图形约 24px，点击区域至少 44 × 44px。常态不展开文字菜单。
- 上方依次放置 **Codex**、**DSH** 与 **Antigravity** 图标；当前选中项使用柔和玻璃底、高光边缘及明确的选中标记。
- 鼠标悬停或键盘聚焦显示名称提示；按钮有可访问名称与选中状态，不靠图标颜色单独传达身份。
- **⚙️ 设置图标固定在最底部**，与 Agent 图标保持同一视觉尺寸；点击后在同一工作台切换到设置三栏视图（006）。
- 运行中的会话或待审批可在所属 Agent 图标上显示小状态点／数量提示，避免大量闪烁动画。

点击 Agent 图标后，第二栏显示该 Agent 的项目与会话，第三栏恢复该 Agent 上次选中的会话。第一次进入某个 Agent 时显示空状态与新建对话入口。选择图标本身不创建会话、不调用模型。

### 第二栏：按项目组织 Session

在当前 Agent 下，第二栏按项目分组展示对话。项目表示一个明确的本地工作目录；同一项目可以分别拥有三种 Agent 的会话，不同 Agent 的对话不会混在同一个会话中。

顶部显示当前 Agent 名称和“添加项目”入口。项目行支持折叠／展开，并提供该项目的“新建对话”按钮；项目内部的会话按最近活动排序。会话行展示标题、选中态，以及运行中、待审批、失败或已断开的状态。长标题省略，悬停可查看完整内容。

新建对话必须先确定项目，默认标题为“新对话”，首次发送后可用首条消息的简短摘要命名；不额外调用模型生成标题。归档、批量删除和跨 Agent 迁移不在功能范围内。

“添加项目”使用弹层录入名称和本地绝对目录，由本地端确认目录存在并规范化路径。不能把浏览器文件选择器的显示名称当作本机绝对路径。创建 ACP 会话使用所属项目的 `cwd`，不能继续把所有项目绑定到 Stirrup 源码目录；已建立会话的项目归属不随列表选择改变。

#### 宽度与拖动

以下数值是本项目的设计取值，不是 Apple 系统控件的规定：

| 项目 | 约定 |
| --- | --- |
| 百分比基准 | 应用容器内宽 `W`，包含图标栏，扣除页面外侧留白 |
| 初始宽度 | 第二栏默认 `20% × W` |
| 最大宽度 | 不超过 `50% × W`，并为第三栏保留必要空间 |
| 最小宽度 | 桌面布局建议 200px |
| 第三栏保留宽度 | 桌面布局建议至少 420px |
| 拖动位置 | 第二栏右边缘；分隔线视觉轻量，命中区域建议 8px |
| 偏好保存 | 保存比例而非固定像素，窗口变化后重新限制到有效范围 |

桌面宽度计算为：设第一栏宽度 `R = 64px`，`G` 为栏间距与分隔区域总宽，`max = min(0.5 × W, W − R − G − 420px)`；第二栏宽度取 `clamp(200px, ratio × W, max)`，首次 `ratio = 0.2`。第三栏接收全部剩余空间。若空间不足以同时满足最小宽度，进入窄屏布局，不让最小宽度反过来突破 50% 上限。

拖动时捕获指针并暂时禁止文字选择；松开提交比例，取消拖动恢复起始值。双击分隔线恢复默认 20%。键盘聚焦分隔线后，左右方向键每次调整 10px，Home / End 调整到当前最小／最大值；分隔线声明可访问角色、方向及当前宽度。

建议视口小于 1024px 时进入窄屏布局：保留 Agent 窄栏，Session 栏变为由主对话区按钮打开的临时抽屉，选择会话后收起。20%／50% 规则适用于桌面常驻第二栏；窄屏抽屉独立限宽且不撑出横向页面滚动。返回桌面时恢复先前保存的比例。

### 第三栏：对话与 ACP 输出

整体采用 ChatGPT 类似的对话阅读结构：顶部为项目与会话标题，中间为纵向消息流，底部为固定可见的多行输入框及其下方会话配置行。正常消息列建议居中且最大宽度约 880px；代码、差异及工具详情可利用更宽空间，溢出内容在自身容器内滚动。

用户消息右侧对齐并使用轻量圆角底；Agent 回复以清晰排版为主，不给每段文字套玻璃卡片。消息可展示安全渲染的 Markdown、列表和代码块，代码块提供复制按钮；禁用原始 HTML 执行和不安全链接。现有纯文本渲染可作为安全降级方式。

| ACP 内容 | 页面表现 |
| --- | --- |
| 回复片段 | 合并为当前轮次的连续回复，不每个片段创建一条消息 |
| 思考内容 | 单独标识，可折叠；代理未发送时不伪造内容 |
| 工具调用与更新 | 根据 toolCallId 更新同一工具卡，显示标题、运行状态与可展开详情 |
| 执行计划 | 代理提供时展示，并更新其步骤状态 |
| 权限请求 | 在所属会话中显示审批卡，保留代理提供的选项；多个请求分别处理 |
| 配置选项／模式 | 模型、Effort、Fast mode 直接位于输入框下方，模式和其他配置同属该区域；只呈现代理实际支持的内容，详见 007 |
| 结束与错误 | 显示真实 stopReason 或简明错误，可展开技术详情 |
| 暂未专门呈现的事件 | 在可折叠的协议详情中保留可读记录，不把原始 JSON 默认铺满聊天区 |

输入框支持 Enter 发送、Shift + Enter 换行，输入法组合期间不误发送。执行中显示停止按钮，同一会话不接受重叠 prompt；停止后继续等待代理最终响应。各会话独立保存草稿。

用户位于消息底部时跟随新输出；向上查看历史后保持当前位置，显示“有新内容／回到底部”按钮。工具展开、审批出现或流式回复不会强行把用户从历史位置拉走。

未选择项目、没有会话、正在连接、模型认证缺失、断线等情况均使用具体空状态，不用虚假的欢迎回复填充对话。

## Agent、项目与会话的交互边界

**切换会话只切换视图，保留各会话的独立连接、历史与草稿。**

| 操作 | 目标行为 |
| --- | --- |
| Codex 切换到 DSH | 恢复 DSH 的最近选择；Codex 会话、草稿和运行状态保留 |
| 切换项目／会话 | 切换可见内容；返回时保留草稿、滚动位置和工具展开状态 |
| 非当前会话继续输出 | 只更新所属会话记录及列表状态，不追加到当前聊天区 |
| 非当前会话请求审批 | 在会话行和 Agent 图标提示；进入所属会话后处理，不自动批准 |
| 新建对话 | 在选定项目与 Agent 下建立独立会话，完成 session/new 后才允许发送 |
| 主动断开会话 | 关闭对应连接和待决审批；已展示的消息仍可查看 |
| 网络中断／页面刷新 | 不自动重发 prompt；历史展示与协议恢复分别处理 |
| 退出登录 | 若有活动轮次，提示会中断的范围；确认后取消待决审批并关闭该登录会话的连接 |

采用“一个活跃对话对应一个 ACP 连接／代理进程”的模型，由页面协调多个连接；切换视图不关闭它们。无需为了三栏 UI 先实现单连接多会话协议或独立后台调度服务。仅驻留已打开的活跃对话，不为历史列表中的每条记录启动代理。

每条应用会话记录绑定一个项目和一个 Agent，并保存代理返回的 sessionId（建立前可以为空）。应用内记录 ID 用于稳定的列表与页面选择；ACP sessionId 由代理管理；JSON-RPC request ID 仍由 SDK 管理。事件通过所属连接与 sessionId 路由，不能使用当前选中项来推断归属。权限响应只能回到发起请求的连接。

项目索引、会话展示记录等本地状态当前以 SQLite 存入本项目 `.local/web/`，与 `.local/dsh/` 分开并由 `.gitignore` 排除。主题、效果和栏宽保存到个人设置表；浏览器只缓存最近 Agent/会话选择，登录凭据不进入浏览器持久存储。会话正文属于私有运行数据，不提交到仓库。SQLite 表结构、事务、离线迁移及回退流程由 005 定义。

保存了界面历史不等于恢复了 Agent 上下文。重新进入历史会话时，只有在代理公布并实际支持相应 load / resume 能力时才能继续原会话；否则允许查看记录，并明确提供“在此项目新建对话”。恢复失败也保留历史展示，不把整段旧消息自动重发来冒充恢复。待决审批不跨连接重放。历史回放与本地记录若同时存在，需要按来源处理，避免重复追加。

## 设置：同一工作台内的三栏视图

点击第一栏底部 ⚙️ 切换到设置视图，完整操作规则以 [006 · 设置页面](006_settings_page_design.md) 为准：

- 第一栏保持 Codex、DSH、Antigravity 和底部齿轮，齿轮显示当前选中状态；点击 Agent 返回其最近对话。
- 第二栏显示“外观”“Agent”“账号与安全”“数据存储”分类，沿用默认 20%、最大 50% 的可调栏宽。
- 第三栏显示所选分类的设置项，沿用工作台材料、圆角与阅读底色；不出现覆盖工作台的遮罩或设置 dialog。

设置拥有 `/settings/:section` 路由，支持刷新和浏览器返回。切换期间保留后台连接、流式输出、草稿、阅读位置和待处理审批，不销毁工作台状态。Escape 不关闭设置视图。

外观选项即时生效并保存到个人设置表；账号和存储信息来自已鉴权接口，不回显凭据。Passkey 与登录有效期由个人设置表管理。模型、推理强度、Fast mode 和操作模式属于第三栏输入框下方的会话配置，遵循 007；项目添加仍属于对话视图第二栏。

## Apple Liquid Glass 风格

采用轻盈、半透明、圆角、细边缘高光与柔和阴影构成的视觉层级。玻璃主要用于图标导航、项目侧栏、标题工具条、输入框和设置控件；消息正文保留稳定清晰的阅读底色。这遵循 Apple 将 Liquid Glass 主要用于导航和控制层的材料分层思路。[Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)

以下为本项目建议的 Web 视觉参数，实施时以明暗背景下的可读性校准：

| 项目 | 设计方向 |
| --- | --- |
| 页面背景 | 接近白／深石墨色的底色，带少量低饱和蓝灰渐变 |
| 玻璃表面 | 半透明填充、适度 backdrop blur / saturation；避免连续叠加多层模糊 |
| 边缘 | 约 1px 的细描边及轻微内侧高光，减少厚重框线 |
| 圆角 | 主面板建议 20–24px，普通控件 10–14px，图标选中底为圆角方形 |
| 阴影 | 低透明度、较大扩散范围，以分层为目的 |
| 强调色 | 单一克制的蓝色，错误／运行／审批状态辅以文字或形状 |
| 字体 | 使用系统字体栈；代码使用等宽字体，正文保持足够行高 |
| 动效 | 建议 140–220ms 的淡入、选中态和短距离过渡；流式输出不逐字做装饰动画 |

Web 通过 CSS 材料效果表达该风格，不宣称复现 Apple 原生光学渲染。避免大面积高饱和背景、强折射文字、不断流动的装饰背景，以及对每条消息使用玻璃。

同时提供浅色与深色样式。检测到减少动态效果偏好时关闭装饰位移；用户开启减少透明效果或浏览器不支持 `backdrop-filter` 时采用更实的面板底色。键盘焦点清晰，正文与控件在实际叠加背景上保持可读，审批与错误提示不会因透明效果变淡。

## 验收标准

| 编号与功能 | 验收要求 |
| --- | --- |
| WEB-01：启动与登录 | 登录页与工作台路由、登录检查、退出流程；未认证请求无法访问私有数据或建立 ACP 连接 |
| WEB-02：三栏框架 | 第一栏为单列图标，三种 Agent 在上、设置在下；第二栏默认 20%、最大 50%，拖动与键盘调整可用 |
| WEB-03：项目与会话 | 按项目显示会话；创建使用正确 cwd；切换 Agent／会话保留历史与草稿，输出和审批不串线 |
| WEB-04：对话呈现 | 消息、工具状态、审批、取消、配置接入既有 ACP；滚动跟随与历史阅读行为符合本篇 |
| WEB-05：视觉与适配 | 登录页和主对话页统一 Glass 语言；明暗模式、减少效果、窄屏抽屉可用 |
| WEB-06：三栏设置 | 按 006 复用三栏外壳、分类路由和后台会话状态 |

重点验收场景：

1. 未登录直接访问 `/chat` 回到登录页；登录后刷新仍正确校验，不暴露前一登录状态的私有消息。
2. 桌面第二栏初始为 20%；拖到最右不超过 50%，窗口缩小时仍保留对话空间；刷新后恢复有效比例。
3. 同一项目分别创建 Codex、DSH 对话；不同项目创建同一 Agent 的对话，各自 cwd 与消息归属正确。
4. Codex 回复中切换到 DSH，再切回时原回复仍连续，DSH 页面没有混入 Codex 内容。
5. 后台会话出现审批时有提示；只能在正确会话中回答，关闭连接后旧审批不再可操作。
6. 浏览历史时新消息不会抢滚动；切换会话保留各自草稿和阅读位置。
7. 刷新后，能恢复与只能浏览的历史会话有明确区分；不会重复发送旧 prompt。
8. 点击底部齿轮后保持工作台三栏：图标导航、设置分类、设置内容；无设置弹窗。返回 Agent 恢复原会话，后台轮次与审批保持正确归属，详见 006 验收。
9. 深色、浅色、关闭透明效果和窄屏下均可读、可操作；输入法 Enter 不误提交。

## 运行边界

会话记录以完整快照保存，每次请求上限 8 MiB、单条消息文本上限 100 万字符、最多 5000 条消息；超限会展示保存错误。流式内容约 500ms 合并保存，轮次结束和主动退出会立即保存；浏览器强制关闭或进程崩溃可能丢失尚未提交的尾部内容。刷新会断开当前页面的代理进程，恢复必须由代理实际支持。多窗口同时修改同一会话会被版本检查拒绝，界面提示刷新，不覆盖另一窗口的数据。

Passkey 丢失时没有密码恢复入口；需由服务器文件所有者停止服务并备份数据库后维护个人记录。不得因域名不匹配或读取失败自动删除账号。验收执行结果统一记录在 [CHANGELOG.md](../CHANGELOG.md)。
