# 006 · 三栏设置页面与操作约定

## 范围与布局约定

设置由 `src/ui/pages/settings.ts` 和 `src/ui/settings/` 渲染在三栏工作台中。

**设置必须沿用首页的三栏工作台：第一栏为 Agent/设置图标，第二栏为设置分类，第三栏为所选分类的内容。设置主内容不得放在 dialog、模态遮罩、居中卡片弹窗或独立单栏页面中。** 设置布局和操作以本篇为准。

产品保留“登录页 + 登录后的工作台”两个页面层级；工作台包含对话和设置两种内容视图。设置有自己的可导航 URL，但共享同一个三栏外壳、登录状态和对话运行实例，不另起一套布局。[003 · Web 基础约定](003_web_app_design.md)

### 第一栏：保留全局导航

- 三种 Agent 图标位置不变，⚙️ 始终在底部。进入设置后只将齿轮标记为当前导航项，不同时把某个 Agent 标记为当前页面。
- 内部保留此前选择的 Agent、项目及会话；点击任一 Agent 图标返回该 Agent 最近选择的对话，缺少选择时显示对应空状态。
- 后台运行和待审批提示仍更新在 Agent 图标上，不因为进入设置而消失。
- 再次点击已选中的齿轮保持当前设置分类，不把它当作弹窗开关，也不切回聊天。

### 第二栏：设置分类

第二栏标题改为“设置”，列表仅包含“外观、Agent、账号与安全、数据存储”。这里不混排项目会话，不展示添加项目或新建对话按钮。分类选中态、键盘焦点和文字截断规则与会话侧栏一致。

共享 003 的布局参数：第一栏 64px，第二栏初始为工作台容器内宽的 20%，最多 50%、建议最小 200px，第三栏保留至少 420px；比例按可用宽度约束。分隔线支持指针拖动、方向键、Home/End、双击恢复。聊天与设置共用同一个栏宽偏好，切换不重置比例。

窄于 1024px 时，第二栏变为分类抽屉，第三栏提供“打开设置分类”按钮；选中分类后收起。第三栏设置内容仍在主工作台中，不能把窄屏设置整体改成模态窗口。返回桌面恢复已保存比例。

### 第三栏：设置内容

顶部显示“设置 / 当前分类”，下方按组排列标签、控件和说明；内容超出时仅内容区纵向滚动。隐藏会话标题工具栏、消息输入框和聊天审批面板，第一栏仍能提示后台事件。

延续首页的 Liquid Glass 颜色、圆角、间距和明暗主题。玻璃用于导航与控件容器，表单正文保持稳定可读的底色；不在整页上额外叠加模糊遮罩。每个控件有可见标签、键盘焦点和明确反馈，不能只靠颜色表达状态。

## 路由、进入与返回

| URL | 行为 |
| --- | --- |
| `/settings` | 规范化到 `/settings/appearance` |
| `/settings/appearance` | 外观分类 |
| `/settings/agents` | Agent 连接配置与状态 |
| `/settings/account` | 单用户 Passkey 与登录会话信息 |
| `/settings/storage` | 应用数据存储信息 |
| 未知 `/settings/:section` | 用 replaceState 回到外观，不渲染空白页 |

从聊天点击齿轮，通过工作台内导航进入设置；初次默认为外观，同一次工作台生命周期内再次进入时保留上次分类。进入设置使用 `pushState`，分类切换使用 `replaceState`，避免浏览器返回键逐条经过所有分类；`popstate` 必须能在聊天和设置之间恢复相应视图。直接访问分类 URL 时先鉴权，通过后显示该分类。需要登录时保留经过白名单校验的工作台目标路由，登录成功后恢复；不得接受外部 URL 作为返回地址。

点击 Agent 图标通过应用内导航进入该 Agent 的聊天视图。直接进入设置而没有上一段聊天历史时，使用保存的最近选择；选择失效则显示空状态，不新建会话。URL 不包含本地绝对路径、密钥或 Passkey 凭证。

未登录或登录到期：显示登录页并清除私有界面，服务端继续按现有机制拒绝请求、关闭 ACP 连接。`/settings` 的前端路由不能代替接口鉴权。Escape 不关闭设置页面；其作用只限于取消正在进行的拖动或关闭窄屏分类抽屉。

## 分类操作

### 外观

| 操作 | 生效与保存 | 失败反馈 |
| --- | --- | --- |
| 跟随系统 / 浅色 / 深色 | 选择后立即应用到整个工作台，保存 `theme`；跟随系统继续监听系统变化 | 浏览器持久化失败时提示“本次生效，但未能保存到此浏览器” |
| 减少透明效果 | 立即切换更实的材料底色，保存 `opaque` | 同上 |
| 减少动态效果 | 立即减少过渡，保存 `motion`；系统减少动态偏好仍优先得到满足 | 同上 |
| 恢复默认栏宽 | 将共享比例设为 0.2，重新按窗口限宽计算，保存 `ratio` | 提示成功或仅临时生效，不清除主题和会话选择 |

这些是即时生效的偏好，不设置一个没有实际意义的总“保存”按钮。每项只改变自身字段，保留 `agent`、`selected` 等其他偏好；切换分类或离开设置不要求“保存整页”。不在 `localStorage` 中保存登录令牌、消息或模型密钥。

### Agent：连接配置与状态

为 **Codex、DSH、Antigravity（AGY）** 分别提供独立的连接配置。第三栏按 Agent 分组展示，每组包含连接方式、地址表单、保存/撤销、测试连接和当前会话状态；不在第二栏新增项目或会话。这里配置的是 **ACP 服务地址**，不是模型 API Base URL、HTTP 代理或 Stirrup 自身的监听端口。

#### 连接字段

| 字段 | 本地 CLI | 自定义 ACP 服务 |
| --- | --- | --- |
| 连接方式 | 默认；由本地服务启动官方 CLI | 连接已经运行的兼容 ACP 服务，不启动 CLI |
| 应用协议 | ACP v1，固定 | ACP v1，固定；通过 initialize 校验 |
| 传输 | stdio，固定，无地址端口 | WebSocket：`ws` 或 `wss` |
| 主机地址 | 不显示 | 域名、IPv4 或 IPv6；不包含协议、端口或路径 |
| 端口 | 不显示 | 整数 1–65535；ws 默认 80，wss 默认 443，可显式修改 |
| 服务路径 | 不显示 | 以 `/` 开头，如 `/acp`；没有统一默认路径，必须匹配目标服务 |
| 完整地址 | 展示本地入口说明 | 支持直接粘贴，如 `ws://127.0.0.1:9001/acp`；与拆分字段双向同步 |

完整地址与拆分字段共享一份表单状态，不保存两套可能矛盾的配置。IPv6 完整 URL 使用方括号。拒绝空主机、越界端口、URL 用户名/密码、fragment、查询参数以及不支持的 scheme；切换传输方式时不提交隐藏方式的字段。HTTP/HTTPS 普通 URL、SSE、Streamable HTTP、原始 TCP 不映射成 WebSocket，也不伪装为已支持的 ACP 传输。

本地方式保留 [001](001_codex_acp.md)、[002](002_dsh_acp.md)、[008](008_agy_acp.md) 的固定启动约定。网络方式的地址由运行 Stirrup 后端的机器解析和连接；`localhost` 指该机器，不是浏览器所在机器。页面始终连接 Stirrup 同源入口，不能绕过登录直接连接远端。

#### 网络传输兼容边界

本设计的网络选项明确标注为 **ACP v1 / WebSocket NDJSON 转接**：每个连接承载一条独立 ACP 字节流，UTF-8 JSON-RPC 消息以换行分隔；消息可以跨 WebSocket 帧或合并于一帧，双方都不得把单个帧当作完整 RPC 的保证。连接必须支持双向请求、通知和权限应答，不能仅提供单向输出。帧上限沿用本地桥接的 1 MiB。

这是 Stirrup 的明确兼容契约，不意味着任意 ACP 服务都支持相同 WebSocket 封装。官方 CLI 的 stdio 入口不会因为填写端口自动变成网络服务；目标端须提供兼容转接。协议与网络传输区分参见 [ACP 官方传输说明](https://github.com/agentclientprotocol/agent-client-protocol/blob/main/docs/protocol/v2/migration.mdx)。不通过连接失败自动降级协议、忽略 TLS 校验或改走其他地址。

远端必须能访问会话项目的绝对路径；本设计使用相同 cwd，不做本地文件同步或路径映射。路径在远端不存在时明确报建会话失败。本页不新增 API Key 或任意请求头输入，首版仅对接无需额外传输层凭据的服务；Agent 自身认证仍使用其公布的 ACP 方法。需要额外网络认证的服务须先补齐对应契约，不能把令牌塞进 URL。

#### 保存、测试与生效

- 每个 Agent 有独立“保存”“撤销修改”“测试连接”按钮。编辑不立即连接，保存只校验并持久化配置，不发送模型请求；读取或保存失败保留草稿并允许重试。
- “测试连接”使用当前表单草稿，建立临时连接并完成 ACP `initialize`，20 秒内结束；不调用 authenticate、session/new 或 prompt，不接受工具审批。成功、失败、取消或登录到期均关闭临时资源。结果区分网络失败、TLS 失败、协议不兼容和握手成功；握手成功不代表模型认证或项目路径已验证。表单变动后将旧测试结果标为过期。
- 保存后对新建连接生效，不中断进行中的输出或审批；界面明确提示已有连接仍使用原配置。不得自动重启全部 Agent 或重新发送消息。
- 历史会话的 providerSessionId 只可发回创建它的连接目标。建立会话时保存规范化目标标识；连接方式或地址改变后，旧会话保留阅读能力，但阻止向新目标恢复，提示恢复原配置或新建会话。原有未记录目标的会话视为本地 CLI 来源。相同地址背后服务被替换而拒绝恢复时，同样保留历史并提示新建，不自动重放。
- 各 Agent 当前连接数、执行/待审批数仍取自已有工作台状态，不因打开设置额外启动进程。“查看对话”返回对应 Agent 最近选择；无会话时显示空状态。
- 模型、推理强度、Fast mode、操作模式仍属于具体会话，按 [007](007_conversation_product_design.md) 在输入区配置。设置页不代答后台审批，不提供全局自动批准。

### 账号与安全

显示固定单用户的名称、认证方式“Passkey”、当前登录的到期时间，以及 `.env` 配置的后续登录有效期。两种时间明确区分：修改 `.env` 不会延长已经建立的登录 Session。

名称、Passkey 与 `STIRRUP_SESSION_TTL_SECONDS` 均只读，配置来源仍是 `.env`。可说明去本机修改配置及重新登录生效，不增加网页密码、用户名修改或公钥替换表单，不返回原始凭证、公钥 JSON、Cookie 或绑定授权。

“退出登录”的操作顺序：

1. 在第三栏展开退出确认区，提供“取消”和“确认退出”；不把整个设置页面装进确认弹窗。
2. 显示当前有多少操作/待审批会被中断。取消只收起确认区，保留分类和所有连接。
3. 确认后禁用重复提交，关闭该工作台的活动客户端并取消未决审批，flush 当前消息和草稿。
4. 保存成功后调用现有退出接口，服务端撤销 Session 及其连接，客户端释放工作台状态并回到登录页。
5. 保存失败时保留登录并显示错误，允许处理后重试；已经停止的操作不会自动重启。退出请求失败时也不能提前宣称已退出。

### 数据存储

展示当前后端类型和应用数据位置，并解释应用历史与 Agent 上下文的区别。SQLite 存储及迁移流程以 [005 · SQLite 存储](005_sqlite_storage_design.md) 为准。

| 展示项 | 约定 |
| --- | --- |
| 当前存储方式 | 后端确认的 `JSON 文件` 或 `SQLite`，不能因为文档已完成就显示“已迁移” |
| 应用数据位置 | 已登录用户可见的本地应用路径；只读，不允许从页面切换到任意数据库文件 |
| 结构版本 | 数据库实际 schema 版本号（如 v1），不是 SQLite 引擎版本；JSON 后端显示“不适用” |
| 项目/对话/消息数量 | 来自已授权的实际存储读取，不通过导出全部正文来统计 |
| Agent 上下文 | 提示由 Codex / DSH / Antigravity 自己管理；没有恢复能力时历史仍可阅读 |

统计读取失败时显示具体读取失败状态，不能显示为 0。此页不提供浏览器热迁移、一键清空、覆盖导入或下载整个私有数据库。迁移和离线回退按 005 执行，不通过设置页自动触发。

## 数据来源与最小接口

外观直接复用 `app/preferences.ts`；Agent 运行状态来自已存在的 `WorkspaceController`，连接配置由后端持久化；退出复用 `POST /api/logout`。为 `.env` 有效期、当前 Session 到期时间和存储元信息，提供只读 `GET /api/settings`。

返回只含设置页实际展示的安全投影：

```json
{
  "account": {
    "username": "Stirrup",
    "authMethod": "passkey",
    "configuredSessionTtlSeconds": 43200,
    "currentSessionExpiresAt": 1795392000000
  },
  "storage": {
    "backend": "sqlite",
    "location": ".local/web/stirrup.sqlite",
    "schemaVersion": 1,
    "projectCount": 2,
    "conversationCount": 8,
    "messageCount": 120
  }
}
```

此示例说明响应形状，数值不代表当前实例。JSON 后端的 `location` 为 `.local/web/`、`schemaVersion` 为 null。接口必须鉴权、同源、`Cache-Control: no-store`；未登录返回 401。配置或存储读取失败返回明确错误，不返回占位成功数据。禁止把整个 `.env`、进程环境、登录对象或数据库内容直接序列化给页面。

进入相关分类时加载，支持明确“重试”，不在每个 ACP 文本片段到达时重查数据库。不提供写登录 `.env` 或任意修改数据库的接口；Agent 配置通过以下专用接口保存。

### Agent 配置接口

以下为连接配置的接口契约，与只读 `/api/settings` 摘要分开：

| 接口 | 行为 |
| --- | --- |
| `GET /api/settings/agents` | 返回三个 Agent 的已保存配置、revision；无记录时返回本地 CLI 默认值 |
| `PUT /api/settings/agents/:agentId` | 提交完整配置和读取时的 revision；校验后原子保存并返回新 revision，冲突返回 409 |
| `POST /api/settings/agents/:agentId/test` | 测试请求中的配置草稿，只返回握手结果或经过清理的错误，不保存 |

配置是判别联合：本地为 `{ "transport": "stdio" }`；网络为 `{ "transport": "websocket", "url": "ws://127.0.0.1:9001/acp" }`。ACP 版本固定为 1，不能任意输入。服务端统一规范化 URL、校验 Agent 白名单与未知字段；不会将请求内容拼接成 shell 命令。PUT 成功只表示保存成功，与测试结果分开。

配置在服务端 SQLite 按 Agent 持久化，不能只存浏览器 localStorage；通过受控 schema 迁移增加配置记录及会话连接目标标识，保留现有历史。配置不含密钥；不把目标地址写入浏览器导航 URL。失败回滚，不用默认值掩盖损坏数据。

所有接口要求登录、Host/Origin 校验及 `Cache-Control: no-store`。网络连接只使用已保存且经校验的配置；测试使用本次经校验的草稿。测试取消和登录失效必须释放网络资源，服务端不跟随重定向或自动切换目标。已有会话仍受项目、Agent、登录及单连接约束保护。

## 工作台状态与代码边界

进入设置只切换内容视图。应用层必须持有同一个 `WorkspaceController` 与每会话的阅读状态，保存中的请求和后台流式通知继续归属于原会话。不能复用退出登录的 `disposeWorkspace()` 来实现设置导航，也不能在返回聊天时重新 `load()` 覆盖仍在运行的对象。

需要保留的状态包括：Agent/项目/会话选择、草稿、消息、流式合并、审批请求身份、各会话滚动位置与展开项、保存队列和失败提示。滚动/展开项仍是 UI 状态，不为实现保留而挪入数据库或 ACP 模型。刷新页面仍按既有断线和恢复能力规则处理，不假装支持跨刷新运行。

模块职责：

| 模块 | 改动职责 |
| --- | --- |
| `src/app/routes.ts` | 增加设置分类路由、前进/后退和 URL 归一化 |
| `src/app/application.ts` | 持有同一工作台控制器和页面；仅登录生命周期变化时销毁 |
| `src/ui/pages/workspace-shell.ts` | 抽出可共享的三栏外壳，保持导航和分隔线一致 |
| `src/ui/pages/settings.ts` | 挂载分类导航、第三栏内容与加载/错误状态 |
| `src/ui/settings/` | 外观、Agent、账号、安全退出确认和存储区域渲染；不直接写文件 |
| `src/ui/dialogs/` | 承载添加项目等短操作；设置主内容不使用弹层，会话配置按 007 放在输入框下方 |
| `src/ui/pages/workspace.ts`、`src/ui/view-state.ts` | 持有工作台生命周期内的阅读状态；聊天 DOM 隐藏时暂停渲染，返回时按原状态更新 |
| `src/ui/styles/` | 为设置内容补充同主题样式，复用三栏宽度及响应式规则 |
| `local/http/routes.ts` | 设置摘要及 Agent 配置/测试接口，委托对应模块校验、保存与测试 |

添加项目等短操作可使用弹层，会话配置按 007 使用输入框下方控件与就近选择菜单；这不改变“设置主页面必须三栏”的要求。无需引入前端框架或通用插件系统来实现本篇。

## 验收清单

1. 点击齿轮后仍能看到三栏，第二栏变成设置分类、第三栏变成设置内容，没有设置 dialog 或全页遮罩。
2. 第一栏图标宽度、底部齿轮位置、20%/50% 栏宽、拖动/键盘及窄屏抽屉与首页一致。
3. 进入、切换分类、返回 Agent、浏览器前进/后退和直接访问设置 URL 均正确；未知分类有明确回退。
4. Codex 回复中进入设置，再切回时消息连续；草稿、滚动与展开状态保持，DSH 不混入 Codex 内容。
5. 在设置中也能看到后台审批提示；切回对应会话才能回答，审批未被替换或默认批准。
6. 外观立即应用，存储失败有反馈；恢复栏宽不重置其他偏好。
7. 账号与安全显示配置有效期和本次到期时间，未回显凭证；取消退出不影响连接，保存/退出失败不伪报成功。
8. 存储页显示真实后端；存储类型由接口实际返回值决定，数量读取失败不显示虚假的 0。
9. 登录到期后私有内容清除，设置接口返回 401；在设置内不会另建不受保护的访问入口。
10. 三个 Agent 的配置独立保存，地址拆分/完整 URL 一致；非法协议、端口、凭据 URL 与未知字段拒绝保存。
11. 保存不打断旧连接，revision 冲突不覆盖他人修改；连接目标改变后不会向新端点提交旧 providerSessionId。
12. 测试连接只做握手并回收资源，失败保留草稿；超时、取消及登录失效都结束测试，不创建模型会话。
13. 本地默认入口保持可用；兼容网络端点能完成双向审批与取消，跨帧/合帧正确；远端 cwd 不存在时明确失败。
14. 登录页仍保持独立布局；浅色、深色、减少效果、键盘焦点和移动端设置分类均可用。
